# AI Commerce Agent V1 design

The user's supplied specification is the implementation brief: a working local
product-research application for evaluating and shortlisting e-commerce ideas.
It must run without credentials, preserve saved products after a restart, and
make assumptions and scoring visible. Only one research analyst is in scope.

## Architecture

Streamlit provides Dashboard, Research, Saved Products and Settings. Pydantic
validates products and structured agent assessments. A source protocol separates
local seed/manual input from future external providers. SQLite stores manual
candidates and complete saved analysis snapshots, keyed by a normalized hash of
product name/category. No SQLAlchemy is needed for these two small tables.

The Product Research Analyst supports deterministic demo mode and an optional
OpenAI Responses API adapter. Demo mode is the default even if a key is present;
the user explicitly chooses live analysis in Settings. Live analyses run only
on the Research form submission. SDK failures/refusals/invalid output fall back
to demo with a visible, sanitized notice. There are no external research tools.

## Data and scoring

Twelve seed products span kitchen, pets, car accessories, travel, office and home
fitness. All seed/manual prices and input scores are marked estimated. Verified
facts are provided exclusively through source evidence, never generated by AI.
No V1 seed or manually added candidate claims verified market evidence.
AI judgements and demo assessments are labeled separately from estimates.

Gross margin = (selling price - product cost) / selling price * 100, rounded to
one decimal for display. It excludes shipping, ads, taxes, platform fees and
returns. Negative margins are valid; their margin score is zero. All prices
must be finite, cost >= 0 and selling price > 0. Profit potential is the
deterministic margin score: clamp(gross margin / 10, 0, 10).

Overall score = 10 * (0.25*demand + 0.25*margin_score + 0.20*trend +
0.15*(10-competition) + 0.15*marketing), rounded to one decimal. Components
are available in details. Scores >= 75 are Strong candidate; >= 55 are Worth
investigating; lower scores are Weak candidate. No score is a success probability.

## Flows

Dashboard loads demo analyses immediately. Research searches local candidates
using case-insensitive query tokens over name/category/description/tags, then
analyzes up to 20 matching candidates. Blank queries list all candidates. Manual
input validates prices and estimates, persists candidates and analyzes the new
entry. Sorting and category/score/margin/recommendation filters are shared by
Research and Saved Products. Selecting a product opens full details and save/
remove controls. A repeated save updates its snapshot without inserting a
duplicate. Removing a saved product does not delete a manual candidate.

## Verification

pytest verifies arithmetic and edge cases, score inversion, model validation,
source search, ranking/filtering, deterministic demo/missing key, structured live
responses and safe fallbacks, SQLite upsert/reopen/delete and manual persistence.
Streamlit AppTest exercises navigation, research, details, save, fresh-session
restart, removal and manual entry without making network calls. Start the real
server and check its local health endpoint. Live API quality remains unverified
without a real key and a deliberately requested live run.
